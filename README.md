# 耳机守护 · BudGuard

> 一个只有 73 KB 的 Android 小工具：耳机离开身边时提醒你，**放回充电仓也能提醒**，并且能说清到底是**左耳、右耳还是充电仓**丢了。

`Android 8.0+` · `Java` · `无网络权限` · `全程离线` · `不需要 Root`

---

## 这是什么

华为/荣耀设备上的「耳机遗落提醒」依赖系统级服务（音频管家 + 云空间 + HMS），第三方应用无法直接调用。
本项目用标准 Android BLE API 重新实现同一件事：**监听耳机自己的蓝牙广播，判断它还在不在身边**，然后在 Android 手机上给出提醒。

不依赖 GMS、不依赖华为服务、不需要 Root，也不申请任何网络权限。

## 功能

| 功能 | 说明 |
|---|---|
| **收纳态遗落提醒** | 耳机在充电仓里（断电不广播）时，靠充电仓自己的 BLE 信标判断"仓还在不在"，**这是本项目的核心场景** |
| **连接态遗落提醒** | 耳机戴着/连着时，监听链路断开（ACL + A2DP 轮询），走出范围或断开即提醒 |
| **部件级判定** | 左耳 / 右耳 / 充电仓 分别建模、分别计时，提醒文案精确到"左耳+耳机仓遗落"等 7 种组合 |
| **仓内确认** | 仓在附近但左右耳静默时，问你一次"耳机是否在仓内"，确认后不再误报左右耳 |
| **四档触发距离** | 形影不离(<1m) / 随身携带(2m) / 待在附近(5m) / 完全断开(仅信号消失) |
| **遗落记录** | 记录时间、各部件最后听到的时刻与位置、判定时刻位置、推定落点、中文地址、可信度；保留 10 条 / 48 小时 |
| **近场查找** | 用 RSSI 估算距离，距离越近震动与提示音越急促，并提示"正在靠近 / 正在远离" |
| **状态常驻通知** | 通知栏实时显示 `在附近` / `左耳+耳机仓遗落` / `在仓内` 等状态与当前距离 |
| **开机自启** | 重启后自动恢复守护 |
| **零网络** | 不申请 INTERNET 权限，数据全部留在本机 |

## 它是怎么工作的

```
耳机/充电仓 ──BLE 广播──▶ 前台服务（15s 扫描 / 20s 停顿）
                              │
                              ├─ 指纹匹配（厂商ID / 服务UUID / 帧类型 / 长度）
                              ├─ RSSI → 距离（对数路径损耗 + 中位数滤波 + 在线噪声估计）
                              ├─ 加速度计判断「人是否真的在走动」
                              └─ 超距 6 秒 → 判定遗落 → 通知 + 记录 + 定位
```

几个关键设计：

- **指纹不含轮换字段**：华为耳机信标会轮换密钥与随机 MAC，指纹只取「厂商 ID + 服务 UUID + 帧类型 + 帧长度」这类稳定部分，因此长期有效。
- **持续扫描不如占空比**：15 秒扫描 / 20 秒停顿，避免频繁 `startScan` 触发系统扫描限流。
- **不拿旧数据下结论**：距离判定只认"扫描中 + 最近 10 秒内的样本"，停顿期一律不判。
- **落点估计**：优先用"最后一次距离 ≤ 2 米时的手机定位"（最接近耳机实际位置），与判定时刻定位按 `1/acc²` 加权融合。
- **防误报三重门**：加速度计移动门控 + 超距持续 6 秒 + 2 分钟提醒冷却。

## 使用

首次配置约 3 分钟。

### 1. 授予权限

首次打开会依次请求：**蓝牙扫描/连接**、**通知**、**精确位置**（用于记录遗落位置）。
位置权限只在前台服务里使用，不会上传。

### 2. 自动校准（关键步骤）

首页点「**自动校准左右耳**」，按提示做三次取放，每次扫 15 秒：

| 步骤 | 你的动作 | 程序得到的结论 |
|---|---|---|
| 1 | 两只耳机都放进充电仓、**盖好** | 过滤 Apple 设备/车钥匙/门锁等噪声，识别出**充电仓**（只展示，不改设置） |
| 2 | 只取出**左耳**戴入耳朵 | 新出现的信号 = **左耳** |
| 3 | 左耳放回、只取出**右耳** 戴入耳朵| 新出现的信号 = **右耳** |

校准完成后首页会显示「左耳 · 右耳 · 充电仓」，之后所有提醒都按部件播报。

> 校准第 1 步必须**关盖**：耳机放回仓会断电停播，这样"还在广播的那个"才一定是充电仓。

### 3. 选择触发距离

| 档位 | 适用场景 |
|---|---|
| 形影不离（< 1 米） | 离开座位就想被提醒 |
| 随身携带（约 2 米） | 日常通勤、办公 |
| 待在附近（约 5 米） | 常把耳机放桌上，偶尔走开 |
| 完全断开 | 只关心"彻底丢了"，不想被打扰 |

> 距离由 RSSI 估算，受遮挡影响；档位越近，噪声裕量越小（实际触发点会比名义值略大 10%–20%）。

### 4. 打开守护

拨开「**收纳态遗落提醒（充电仓内也生效）**」开关，通知栏会出现常驻状态：

```
HUAWEI FreeBuds Pro 3
在附近 · 约 0.8 米
```

遗落时变成：

```
HUAWEI FreeBuds Pro 3
左耳+耳机仓遗落 · 约 6.2 米
```

### 5. 仓内确认

当**充电仓在附近、左右耳都没有广播**时，应用会问一次「耳机是否在充电仓内？」（通知按钮 + 首页卡片）：

- 点「**在仓内**」→ 进入仓内态：不再报左右耳遗落，只守充电仓；
- 点「**不在仓**」→ 立即按正常流程报警，并记录遗落位置；
- **90 秒**不回应 → 按"不在仓"处理（避免漏报）。

左右耳重新出现广播或重新连接后，仓内态自动失效；下次再静默时会重新询问。

### 6. 查看遗落记录

支持「在地图中打开」跳转导航。耳机回到身边后，会询问是否清除这些记录。

| 参数 | 值 | 说明 |
|---|---|---|
| 扫描窗口 / 停顿 | 15 s / 20 s | 占空比，避免扫描限流 |
| 在场判定周期 | 8 s | |
| 样本新鲜度 | ≤ 10 s | 停顿期不判距离 |

| 信标静默判定 | 45 s | 判定"不在身边" |

| 确认超时 | 90 s | 未回应按"不在仓"处理 |

| 记录保留 | 10 条 / 48 h | 自动过期 |

## 权限说明

| 权限 | 用途 |
|---|---|
| `BLUETOOTH_SCAN` / `BLUETOOTH_CONNECT` | 扫描耳机广播、查询连接状态 |
| `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION` | **仅用于记录遗落发生时的手机位置**；Android 11 及以下扫描 BLE 也需要 |
| `POST_NOTIFICATIONS` | 遗落提醒与常驻状态 |
| `FOREGROUND_SERVICE` + `_CONNECTED_DEVICE` + `_LOCATION` | 后台守护与后台定位 |
| `VIBRATE` | 提醒震动 |
| `RECEIVE_BOOT_COMPLETED` | 开机自动恢复守护 |

**没有 `INTERNET` 权限**——应用不联网、不上传任何数据。

## 兼容性

- Android 8.0（API 26）及以上；
- 针对 **HUAWEI FreeBuds Pro 3** 的广播特征实测调校，理论上适用于之后带 BLE 信标的华为耳机（FreeBuds Pro 4 / FreeBuds 6 / FreeClip 等）；
- 其他品牌耳机：本项目按"华为 `sd:fdee` 服务数据"识别，其它品牌通常无法自动识别，可在「探测日志」里查看广播特征后自行适配代码。

## 常见问题

**Q：为什么一定要定位权限？**
A：遗落记录需要保存"当时人在哪"，否则记录里只有时间没有地点。位置只写本地存储，不联网。

**Q：地址一直是空的？**
A：中文地址依赖系统 `Geocoder`，部分机型没有可用的地理编码后端。此时会退化为显示经纬度，坐标仍然可用（可在地图中打开）。

**Q：为什么有时候显示"信号已断开"而不是距离？**
A：超过 20 秒没有新样本就不再显示旧读数。耳机进仓断电、走远到扫不到，都会显示这个。

**Q：会很耗电吗？**
A：属于"持续蓝牙扫描 + 前台服务"类应用。20 秒一次 GPS 定位是主要耗电源，如觉得费电可自行把 `LocTracker.MIN_TIME_MS` 调大。

**Q：会不会误报？**
A：三重门控（移动检测 + 超距持续 6 秒 + 2 分钟冷却）已经把误报压得很低。若你坐着不动仅把耳机放桌上，不会响。

**Q：能替代华为"查找设备"吗？**
A：不能。华为的离线查找依赖其封闭的查找网络（众包上报），第三方无法接入。本项目做的是**本机近场判定**，不提供云端定位、不提供远程响铃。

**Q：支持 iOS / 鸿蒙原生吗？**
A：不支持，本项目是 Android 原生应用。

## 已知限制

1. **无法接入厂商查找网络**：华为/苹果的"离线查找"依赖云端众包，第三方应用没有公开接口。
2. **耳机在仓内断电**：此时只能监测充电仓信标；"左右耳是否在仓内"需要一次人工确认（即上述仓内确认）。
3. **RSSI 距离是估算**：受人体遮挡、墙体、耳机功率影响，误差约 20%–30%，用于判断"远/近"够用，不适合精确测距。
4. **MAC 随机化**：部分耳机使用随机地址，重新配对后可能需要重新校准。
5. **未做大规模机型验证**：目前基于 FreeBuds Pro 3 的实测数据开发，其它机型请以实际效果为准。
